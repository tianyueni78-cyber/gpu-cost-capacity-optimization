# 四产品生产级 SaaS 设计

## 决策

GPU Data、GPU Optimize、GPU Improve、GPU Forecast 保持四个独立产品前台和业务 API，共享控制层。正式前台采用 Next.js，后端采用 FastAPI；现有 Python 领域计算模块不重写。中国大陆环境自建 Supabase，使用 PostgreSQL/RLS、Auth 和对象存储；Redis/Celery 执行长任务。

## 共享控制层

控制层拥有组织、成员、四级角色、项目、产品授权、订阅、连接器、任务和审计事件。所有租户对象同时携带 `organization_id` 与 `project_id`；API 从已验证 JWT 推导用户身份，禁止客户端提交可信的 `owner_id`。数据库 RLS 再次强制组织成员关系。订阅过期后仅允许读取和导出，不允许同步、计算、审批或发布。

角色为 `ORG_ADMIN`、`ANALYST`、`APPROVER`、`VIEWER`。管理员管理成员、连接器和订阅；分析员运行分析；审批人审批 Optimize/Forecast 行动；只读用户仅查看与导出。企业 SSO 通过单个 OIDC/SAML 身份源接入，邮箱登录保留。

## 运行与数据边界

浏览器只调用 FastAPI，不持有数据库高权限密钥。上传文件进入按组织和项目隔离的对象前缀，服务端验证大小、扩展名、MIME 与内容；数据库只保存元数据、规范化结果和证据。敏感凭据使用境内密钥服务包封加密，日志执行字段白名单与敏感值清除。

后台任务必须幂等，状态为 `QUEUED/RUNNING/SUCCEEDED/FAILED/CANCELLED`，记录进度、游标、重试次数和可公开错误码。AWS 连接器只接受只读跨账号角色；Kubernetes/Prometheus 只接受只读服务账号或查询端点。任何连接器均不得执行生产变更。

## 产品边界

- GPU Data 生成通过质量门禁的不可变数据快照。
- GPU Optimize 只消费已通过的数据快照，异步求解并生成待审批方案。
- GPU Improve 消费已审批行动与实际指标，以追加事件验证收益。
- GPU Forecast 保留现有准备度、滚动回测、三模型、区间和不可变版本，再异步生成容量与采购计划。

## 商业、部署与验收

支付宝是首个支付渠道；订单金额和套餐由服务端确定，通知验签且幂等，发票人工处理。开发、预发布、生产完全隔离。生产目标为 99.9% 可用性、RPO 15 分钟、RTO 4 小时；发布前完成恢复演练、跨租户测试、漏洞扫描、ICP备案材料和等保二级准备。真实部署、备案、支付、SSO 和客户连接器授权依赖外部账号，不以仓库代码替代其验收证据。
