# GPU Optimize 容量优化正确性改版设计

## 1. 目标

把当前容量分配 MVP 从“全局 GPU 数量计算”升级为“按兼容范围、共享授权和实际资源池成本生成可审批方案”。本轮优先保证建议安全、可追溯，不增加采购优化、MIG/时间切片配置或自动执行。

## 2. 专业对齐

- FinOps Usage Optimization：建议必须同时考虑成本、性能、可用性、业务约束、实施风险和责任人；
- AWS Compute Optimizer：建议详情应包含当前与推荐配置、预计利用情况、成本和性能风险；
- Azure Advisor：建议应标识影响、受影响资源，并支持推迟、不适用和导出；
- NVIDIA GPU Operator：不同 GPU 型号、MIG 和时间切片具有明确的兼容与隔离边界，不能默认互换。

以上来源用于确定产品原则，不代表本产品复制云厂商算法。跨团队共享规则仍由客户确认。

## 3. 当前问题

1. 当前求解器把不同 GPU 型号和地域汇总为一个容量池，可能产生无法执行的替代；
2. 页面只有共享边界确认复选框，没有记录具体资源池的共享权限；
3. 受影响成本使用费率简单平均值，没有对应到实际调整的资源池；
4. 方案缺少受影响资源、观察期间、计算依据和限制条件；
5. 导出材料没有建议状态和逐资源池调整明细。

在这些问题解决前，产品只能用于算法演示，不应把输出称为可执行的客户容量方案。

## 4. 优化单元

求解器以 `(gpu_model, region)` 作为最小兼容单元。不同单元之间默认禁止替代和共享。

每个资源池必须具有以下输入：

| 字段 | 含义 |
| --- | --- |
| `resource_pool_id` | 可追溯资源池编号 |
| `team_id` | 当前责任团队 |
| `gpu_model` | GPU 型号 |
| `region` | 所在地域 |
| `gpu_count` | 当前数量 |
| `effective_hourly_rate_usd` | 实际有效小时费率 |
| `sharing_scope` | `none`、`team` 或 `cross_team` |

`sharing_scope` 必须由用户逐资源池确认：

- `none`：容量不得移动；
- `team`：只允许在同一团队、同型号、同地域资源池之间调整；
- `cross_team`：允许在同型号、同地域的团队之间进入共享池。

本轮不支持用户自定义型号替代矩阵或跨地域迁移。需要这些能力时另行设计。

## 5. 需求与 SLA 约束

需求必须按 `(team_id, gpu_model, region)` 确认，不能只按团队输入总数。

安全需求为：

```text
minimum_gpu_count = ceil(confirmed_peak_demand × (1 + spare_capacity_pct / 100))
```

求解器不得自动修改确认峰值、备用容量或兼容范围。缺少对应需求、SLA 或共享授权时，相关资源池保持现状并标记为“待确认”。

## 6. 求解模型

每个兼容单元独立建立整数规划：

- 决策变量：各团队保留数量、进入共享池数量、可释放数量；
- 硬约束：团队保留量不低于安全需求；不可共享资源不得移动；所有数量为非负整数；调整后总量不超过该兼容单元库存；
- 第一目标：所有硬约束可行；
- 第二目标：最大化可重新分配或释放的容量；
- 第三目标：同等容量下最小化变更的资源池数量。

如果安全需求超过兼容单元库存，返回该型号、地域和团队对应的缺口。系统不得使用其他型号或地域自动填补。

## 7. 成本口径

受影响成本逐资源池计算：

```text
affected_cost_usd = adjusted_gpu_count × pool_effective_hourly_rate_usd × period_hours
```

方案汇总等于资源池明细求和，不再使用简单平均费率。

容量进入共享池时，默认只产生“成本避免机会”，当前账单节省仍为零。只有资源可以退出采购且合同与费率已经验证时，采购优化模块才能计算理论节省。

## 8. 建议详情

每个建议必须回答：

- 发现了什么；
- 涉及哪些资源池、团队、型号和地域；
- 使用了哪个观察期间；
- 当前配置与建议配置分别是什么；
- 哪些硬约束得到满足；
- 受影响成本是多少；
- 业务影响和 SLA 风险是什么；
- 为什么可能不能实施；
- 需要谁确认下一步。

建议状态仅用于审批管理：

- `待确认`：输入或业务边界仍需补充；
- `待审批`：约束完整且方案可行；
- `推迟`：客户决定稍后处理；
- `不适用`：客户确认该建议不适用于当前资源。

状态变化不修改源数据，也不触发生产操作。

## 9. 页面改版

### 基线接入

保持现有字段映射和审计，新增优化必需字段检查。缺少型号、地域、团队、费率或资源池关联时阻断。

### 目标与约束

按团队、型号和地域显示历史峰值。用户确认需求与备用容量，并逐资源池选择共享范围。保存时生成不可变约束快照。

### 容量优化

先按兼容单元显示求解状态，再显示建议卡和资源池调整明细。不可行单元与可行单元分开呈现，不用全局结果掩盖局部缺口。

### 方案与审批

展示当前、安全调整和低变更方案。支持设置审批状态，导出约束快照、建议明细、资源池调整明细和管理摘要。

## 10. 安全与异常处理

- 任何未确认共享权限的资源池按 `none` 处理；
- 任何无法关联到需求或 SLA 的资源池保持现状；
- 无可行解时只解释冲突，不放松 SLA；
- 未知 GPU 型号可以参与同型号资源池计算，但不得跨型号替代；
- 缺少实际费率时阻断成本计算，不填零、不使用零售价替代；
- 求解器错误与业务不可行必须使用不同状态展示。

## 11. 验收标准

- H100 不会自动替代 A100，地域之间不会自动共享；
- `none` 和 `team` 权限不会产生越权跨团队调整；
- 每个团队、型号、地域的安全需求得到满足；
- 受影响成本等于逐资源池实际费率明细之和；
- 每个建议能追溯到输入资源池、约束快照和观察期间；
- 不可行结果明确指出具体兼容单元及缺口；
- 建议状态可以导出，但不会改变求解结果或生产资源；
- 页面只展示已经实现的容量分配能力。

## 12. 暂不开发

- 跨型号替代矩阵；
- 跨地域迁移；
- MIG 和时间切片配置；
- 预留与 Savings Plan 采购；
- 自动执行、云账号连接和 Kubernetes 写操作；
- 推荐分数、复杂图表和持续监控。
