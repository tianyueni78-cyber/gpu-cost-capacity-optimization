# GPU Optimize 容量分配：30 分钟客户试点

## 试点目标

验证客户能否用真实脱敏数据确认需求与 SLA 约束，获得满足硬约束、可解释且可审批的容量分配方案。

## 客户准备

- 同一期间的 GPU 资源清单、使用记录、云账单和团队 SLA；
- 各团队确认的峰值需求；
- 能够确认共享边界和最终审批责任的人。

## 30 分钟流程

### 0—8 分钟：基线接入

上传四张 CSV、确认字段映射并运行审计。任何阻断项都必须停止求解；不得为了演示绕过数据问题。

### 8—15 分钟：确认约束

逐团队确认峰值需求和 SLA 备用容量。请客户说明系统默认峰值是否符合业务事实，以及哪些资源不得共享。

### 15—22 分钟：容量求解

运行求解器，对比当前、安全释放和低变更方案。验证所有团队保留容量不低于确认需求加备用容量；无可行方案时检查缺口解释。

### 22—27 分钟：口径复核

核对 GPU 数量和受影响成本。明确受影响成本不是已验证节省，共享容量也不会自动降低现有账单。

### 27—30 分钟：审批导出

下载 Markdown 审批报告和方案 CSV。请客户确认责任人、验证步骤和回滚要求；产品不执行生产变更。

## 成功标准

- 四张表能与客户来源对账；
- 约束由客户明确确认；
- 所有可行方案满足硬约束；
- 不可行时准确解释容量缺口；
- 客户理解受影响成本、理论节省和实际节省的区别；
- 导出材料足以支持一次内部评审。

## 记录结果

记录字段映射问题、约束缺失、误报、漏报、求解时间和客户是否愿意用该报告发起审批。相同问题在多个试点重复出现后，再进入产品规则。
