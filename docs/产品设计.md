# GPU Cost & Capacity Copilot｜产品设计

## 1. 产品定位

### 目标用户

GPU 月支出较高、但没有专职 FinOps 团队的中小型 AI 公司，其直接使用者通常是云基础设施负责人、平台工程负责人或技术顾问。

### 核心问题

用户拥有账单和监控数据，却难以回答：

1. GPU 成本由哪些团队、型号、区域和采购方式产生；
2. 当前低利用率是浪费、业务保护容量还是暂时波动；
3. 未来业务增长需要多少 GPU；
4. 哪些按需资源可以释放，哪些承诺容量应在续约时调整；
5. 哪些容量可以跨团队共享，行动会带来多少收益和风险。

### 产品承诺

把分散的 GPU 资源、使用、账单和 SLA 数据转换为可审核的容量与采购行动建议。第一版只辅助决策，不自动执行资源变更。

## 2. 双版本设计

### 公开演示版

- 使用合成数据；
- 无需登录；
- 展示完整分析流程和结果；
- 承担产品介绍和求职作品集功能；
- 不接收真实财务或生产数据。

### 本地客户版

- 使用 Streamlit 提供交互界面；
- 数据在本地进程中读取和计算；
- 分析结束后不长期保留上传文件；
- 报告由用户主动导出；
- 不需要数据库、用户系统、GPU或公共服务器。

## 3. 客户操作流程

### 第一步：创建分析项目

输入项目名称、分析期间、币种和主要目标。目标可选择降成本、保容量或成本与容量平衡。

### 第二步：导入数据

必需数据：

- GPU 资源清单；
- GPU 使用记录；
- 云账单；
- 团队 SLA。

业务事件和外部需求预测为可选输入。产品提供标准 CSV 示例，但不强制客户沿用相同列名。

### 第三步：字段映射

系统根据列名和样例值推荐字段关系，用户逐项确认。字段分为：

- 必需字段：缺失时阻断对应分析；
- 条件必需字段：仅在特定采购或负载场景下要求；
- 可选字段：缺失时降低分析深度，但不阻断基础结果。

完全自动映射不进入第一版，避免错误字段被静默用于金额或容量计算。

### 第四步：数据审计

审计范围包括：

- 主键和业务键重复；
- 必填字段缺失；
- 数值范围和枚举值；
- ID 格式和标准化后关联率；
- 时间覆盖、时区和跨月关系；
- 账单金额公式；
- JOIN 前后行数、主键数和金额对账。

结果分为阻断、警告和通过。阻断问题不允许进入会产生错误决策的后续模块；警告必须保留在最终报告中。

### 第五步：基线分析

输出总成本、成本趋势、采购结构、团队归因、GPU 型号与区域结构、利用率、单位成本和 SLA 表现。成本计算与未使用承诺等管理指标分开，避免重复计入。

### 第六步：容量预测

按业务量单位和负载类型分别预测，使用时间顺序切分和滚动回测选择基线模型。容量换算同时考虑历史峰值系数、SLA 最低备用容量和预测情景。

### 第七步：优化建议

第一版支持：

1. 释放可验证的富余按需容量；
2. 在合同续约窗口调整承诺容量；
3. 匹配同区域、同型号且负载兼容的团队间共享容量；
4. 标记无法通过现有容量解决的局部缺口。

近期节省、续约节省和避免采购金额必须分开，互斥行动不得重复累加。

### 第八步：风险与报告

每条建议展示行动、计算证据、理论价值、SLA影响、风险等级、适用条件和人工确认项。可导出管理层摘要、数据质量报告、容量预测和行动清单。

## 4. 最小技术结构

```text
Streamlit 界面
    ↓
字段映射与输入验证
    ↓
Pandas / DuckDB 数据处理
    ↓
现有成本、预测与优化模块
    ↓
图表、CSV和Markdown报告
```

第一版复用现有分析项目中的清洗、预测、优化和测试逻辑。优化先使用可解释规则或开源求解器，不增加商业求解器授权成本。

## 5. 错误与安全边界

- 文件格式错误：指出文件和字段，不进入计算；
- 必需字段无法映射：阻断相关模块；
- 金额或连接对账失败：阻断成本建议；
- SLA 数据不足：不得生成低风险缩容建议；
- 预测样本不足：只展示历史基线并标注无法可靠预测；
- 无可行优化方案：明确展示约束冲突，不伪造建议；
- 原始文件：不写入代码仓库，不进入公开演示环境；
- 生产操作：产品只导出建议，不调用云平台执行接口。

## 6. 验证标准

- 两套不同列名的数据都能完成引导式映射；
- 已知重复、空值、非法范围和关联问题能被正确发现；
- 账单连接前后金额一致；
- 容量建议不低于预测需求、峰值与 SLA 备用要求；
- 互斥收益不会重复相加；
- 清洗、预测、优化和报告核心规则具备自动测试；
-公开演示数据与客户本地数据严格分离；
- 新用户按照页面提示可以独立完成一次分析并导出报告。

## 7. 变现路径

### 第一阶段：单次诊断

产品完成标准分析，人工审核口径和建议后交付。收费对象是完整诊断结果，而不是软件账号。

### 第二阶段：持续监控

客户定期导入新数据，比较成本、容量和行动执行效果，按月或按季度订阅。

### 第三阶段：企业集成

在真实需求和数据安全方案得到验证后，再增加云账单接口、账号权限、历史数据库和审批式资源操作。

## 8. 暂不实现

- 实时GPU任务调度；
- 自动修改云资源；
- 多租户账号与在线支付；
- 公共环境存储真实账单；
- Kubernetes或云厂商自动接入；
- 大模型训练和GPU推理；
- 为尚未出现的客户需求预留复杂扩展层。
