# 学习与作品资产路线

## 1. 什么才算资产

本项目只承认两类学习资产：

### 可复用资产

换一家公司、数据集或业务问题后仍可使用的模板、代码骨架和验收规则。模板必须说明使用场景、输入、可替换位置、固定步骤和自检方法。

### 展示资产

能够向招聘者或客户证明能力的完整作品集。它必须包含业务问题、数据、方法、验证、结果、风险和可运行交付物。

原始日志、终端输出、零散笔记、课程打卡和未经验证的代码只是过程材料，不自动算资产。只有被提炼进可复用模板，或成为完整作品集证据后，才算资产。

## 2. 四项共同硬能力

目标岗位虽然横跨运筹优化、容量规划、FinOps、供应链和实时决策，但共同主线可以收敛为：

```text
可信数据
→ 预测未来
→ 优化决策
→ 验证有效
```

### 2.1 建立可信决策数据

现实工作流：

```text
原始业务数据
→ 理解表、字段和粒度
→ 审计
→ 清洗
→ 关联
→ 指标计算
→ 对账验证
```

必须亲自掌握：

- 一行数据代表什么；
- 主键和业务键是什么；
- 指标应调用哪张表；
- 两张表能否按当前键直接连接；
- JOIN 后行数和金额为什么变化；
- 时间、单位和粒度是否一致；
- 指标是否重复、漏算或错配。

SQL负责查询、关联、聚合和指标计算；Pandas负责复杂清洗、规则处理和可重复流水线。无需从空白默写所有语法，但必须能追踪并验收AI生成的代码。

可复用资产：

- 数据认识模板；
- 数据审计SQL模板；
- JOIN前后对账模板；
- 指标—字段—时间—粒度映射模板；
- Pandas清洗与验证骨架。

展示资产：

- 原始数据到可信分析表的完整案例；
- 审计发现、清洗决策和验证结果；
- 对关键业务错误的发现与阻断证据。

参考：[Python for Data Analysis 第三版](https://wesmckinney.com/book/)。重点学习数据加载、缺失值、合并、分组和时间数据，不按章节顺序背书。

### 2.2 预测未来决策输入

现实场景包括GPU容量、SKU销量、骑手供需和能源负荷预测。

必须亲自掌握：

- 预测对象和时间粒度；
- 时间序列训练集与测试集划分；
- 朴素基线；
- 滚动回测；
- MAE、RMSE、MAPE的使用条件；
- 时间泄漏；
- 预测误差如何影响容量、库存或调度决策；
- 点预测和预测区间的区别。

可复用资产：

- 时间切分与滚动回测模板；
- 预测baseline模板；
- 泄漏检查表；
- 误差评价与模型选择模板；
- 预测区间到资源需求的转换模板。

展示资产：

- 预测模型与朴素基线的公平比较；
- 预测误差如何改变后续优化结果；
- 可重复运行的预测流水线。

参考：[Forecasting: Principles and Practice](https://otexts.com/fpp3/)。重点学习预测逻辑，不要求沿用书中的R语言。

### 2.3 形式化并求解优化问题

现实工作流：

```text
业务决策
→ 集合和参数
→ 决策变量
→ 目标函数
→ 约束
→ 求解
→ 业务验收
```

必须亲自掌握：

- 参数和变量的区别；
- 变量的业务含义；
- 目标函数是否代表真实目标；
- 业务规则如何翻译成数学约束；
- 单位、索引和时间是否一致；
- 无解、无界和错误最优解如何诊断；
- 如何与现行方案比较；
- 如何进行敏感性和情景分析。

可复用资产：

- MILP建模说明书模板；
- 容量、供需平衡、分配、选择、顺序和SLA约束模式；
- 可行性诊断模板；
- baseline、情景与敏感性分析模板。

展示资产：

- 数学模型和代码实现；
- baseline与优化方案对比；
- 可行性验证；
- 风险、失败场景和适用边界。

参考：[Gurobi官方建模案例](https://gurobi.github.io/modeling-examples/)。收费产品不得直接依赖学术许可证，第一版产品优先使用规则或开源求解器。

### 2.4 验证决策是否真正有效

必须亲自掌握：

- baseline设计；
- 控制变量；
- 离线回测；
- 消融实验；
- 随机种子和稳定性；
- 极端场景和压力测试；
- 主指标、护栏指标和业务价值；
- 结果是否能够复现；
- 上线条件和回滚条件。

可复用资产：

- 决策模型统一验收模板；
- baseline和控制变量模板；
- 回测、敏感性和极端场景模板；
- 上线护栏与回滚标准模板。

展示资产：

- 模型与baseline的公平实验；
- 稳定性与失败案例；
- 成本、质量和SLA的联合验收。

在线决策岗位再补A/B测试和因果推断。参考：[Trustworthy Online Controlled Experiments](https://www.cambridge.org/core/books/trustworthy-online-controlled-experiments/D97B26382EB0EB2DC2019A7A7B518F59)。

## 4. 三个展示项目

### GPU成本与容量决策产品

证明可信数据、成本分析、容量预测、优化规则、产品设计和交付能力。

### 零售需求预测与库存优化

证明预测结果能够进入MILP决策，并量化预测误差对库存、缺货和成本的影响。

### 机器—AGV动态调度研究

证明复杂优化、动态事件处理、算法实验和科研深度。

三个项目应复用同一套数据、预测、建模和验收模板，而不是重复建立三套学习笔记。

## 5. 手机学习如何进入资产

手机只负责短时训练和收集原料，电脑负责验证和资产化。

```text
3分钟：阅读一段SQL或Python，判断输入、动作和输出
5分钟：完成一道SQL/Python机械练习
10分钟：复习业务语言与代码动作的对应关系
15分钟：在Colab或Replit修改一个参数并运行验证
每周：只提炼一个真正复用过的规则进入模板库
```

DataCamp或SoloLearn二选一，负责语法手感；GitHub Mobile用于查看与评审；Colab或Replit用于运行小型真实代码。

一道练习、一个Issue或一个Notebook草稿都不是资产。它必须经过：

```text
在真实项目中使用
→ 自己解释其作用
→ 通过测试或对账
→ 提炼为模板或作品集证据
```

## 6. 与AI的固定分工

AI可以生成查询、代码、测试初稿、图表和报告草稿。本人必须负责：

- 指定数据粒度和指标口径；
- 判断表是否应该连接；
- 审核时间、单位、金额和约束；
- 判断预测和优化是否可用于决策；
- 设计baseline与验收条件；
- 识别错误结果并决定是否接受建议。

目标不是和AI比赛默写语法，而是能够约束、检查和复用AI生产的技术成果。
