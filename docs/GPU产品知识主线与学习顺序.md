# GPU产品知识主线与学习顺序

## 1. 学习目标

目标不是先成为 GPU 底层调度研发工程师，而是做出能够解决真实企业问题、具备付费价值的 GPU 成本与容量优化产品。

产品本质是四个领域的交叉：

```text
Cloud FinOps
+ GPU Capacity Planning
+ Scheduling
+ Data Product
```

技术难度不自动等于商业价值。学习优先级应由产品问题决定：客户为什么付费、需要什么数据、系统给出什么行动、怎样证明收益且不破坏 SLA。

## 2. 九条知识主线

### 2.1 GPU工作原理｜必须理解

需要回答：

- GPU 为什么闲置；
- 为什么 GPU 利用率可能只有 30%；
- 为什么显存已满但计算单元没有跑满；
- A100、H100、L40S 的能力和价格为什么不同；
- 训练、在线推理和批处理为什么需要不同容量策略；
- GPU 为什么不能在所有负载之间直接共享；
- MIG 和 vGPU 解决什么隔离与共享问题；
- 排队来自容量不足、资源碎片、调度策略还是任务约束。

建议资料：

- NVIDIA CUDA Programming Guide；
- NVIDIA CUDA Best Practices Guide；
- NVIDIA MIG User Guide；
- *Programming Massively Parallel Processors*。

学习边界：不要求第一阶段独立编写 CUDA 内核。重点理解 GPU 架构、内存、占用率、瓶颈、资源隔离和调度限制，使产品不会把低利用率简单解释为浪费。

对应产品功能：

- GPU 型号与负载兼容性；
- 利用率诊断；
- 共享与缩容风险判断；
- 资源排队原因分类。

### 2.2 云计算与集群资源｜核心基础

需要理解：

- GPU 实例及其计费方式；
- 按需、竞价/抢占、预留和节省计划；
- 集群、节点池、节点、Pod 和资源请求；
- Kubernetes 调度与自动扩缩容；
- GPU 节点、配额、亲和性、污点和容忍；
- 公有云、自有资源和混合资源池的差异。

建议资料：

- *Kubernetes in Action*；
- Kubernetes 官方文档；
- *Cloud Native Infrastructure*；
- AWS、Azure、GCP及国内目标云厂商的 GPU 实例和计费文档。

学习边界：先做到能够看懂集群结构、资源为什么这样分配和计费，不必立即研究 Kubernetes Scheduler 源码。

对应产品功能：

- 资源清单导入；
- 区域、节点池和型号分析；
- 采购方式比较；
- 扩缩容与资源共享约束。

### 2.3 FinOps｜产品商业核心

需要理解：

- 成本归因；
- Showback 与 Chargeback；
- 预算和预测；
- 按需、预留、节省计划和竞价资源；
- Rightsizing；
- 闲置资源和未使用承诺；
- 单位经济性；
- 成本、业务增长和服务水平之间的权衡。

建议资料：

- *Cloud FinOps*；
- FinOps Foundation Framework、能力模型和实践资料。

对应产品功能：

- 成本仪表盘；
- 团队与业务归因；
- 采购结构分析；
- 闲置与承诺利用诊断；
- 预算、预测和优化建议；
- 节省金额与 ROI 说明。

### 2.4 数据产品与数据质量｜产品可靠性核心

需要理解：

- ETL和数据流水线；
- Schema与字段映射；
- 数据粒度、主键和业务键；
- 批处理、事件和时间口径；
- 一致性与幂等性；
- 数据质量与可追溯性；
- 指标口径和关联前后对账。

建议资料：

- *Designing Data-Intensive Applications*；
- *Python for Data Analysis*；
- SQL关系数据与查询资料。

学习边界：不需要先建设复杂分布式数据平台。第一版重点是可靠读取客户 CSV、完成字段映射、发现数据问题，并证明计算没有重复或漏算。

对应产品功能：

- 数据上传；
- 引导式字段映射；
- 数据审计；
- 清洗与标准化；
- JOIN前后对账；
- 错误阻断和修复建议。

### 2.5 容量预测｜从静态报表进入未来决策

需要理解：

- 时间序列模式；
- 移动平均；
- ETS与ARIMA；
- 朴素基线；
- 时间顺序切分与滚动回测；
- 预测误差；
- 预测区间；
- 预测结果如何换算为GPU容量。

建议资料：

- [Forecasting: Principles and Practice](https://otexts.com/fpp3/)。

学习边界：第一版不需要 LSTM。先证明简单模型经过正确回测，并且预测误差能被带入容量与风险情景。

对应产品功能：

- 业务量预测；
- GPU容量预测；
- 基线、高增长与效率情景；
- 预测误差和安全余量。

### 2.6 运筹优化｜从分析进入行动

需要理解：

- 容量规划；
- 供需平衡；
- 整数规划；
- 资源分配；
- 多目标与软约束；
- 可行性诊断；
- baseline、敏感性和情景分析。

建议资料：

- *Introduction to Operations Research*；
- *Model Building in Mathematical Programming*；
- [Gurobi Modeling Examples](https://gurobi.github.io/modeling-examples/)。

学习边界：重点是把业务规则正确形式化，而不是追求复杂算法。收费产品不能直接使用学术许可证部署 Gurobi；第一版优先使用可解释规则或开源求解器。

对应产品功能：

- 团队间容量共享；
- 采购组合调整；
- GPU型号和区域配置；
- 缩容、扩容和局部缺口；
- 成本与SLA联合约束。

### 2.7 SaaS产品设计｜决定产品是否有人使用

需要理解：

- 产品发现；
- 用户访谈；
- MVP；
- 问题验证；
- 需求优先级；
- 产品指标；
- Roadmap。

建议资料：

- *Inspired*。

对应产品工作：

- 判断客户真正愿意为什么付费；
- 区分“客户需要”与“技术上可以做”；
- 用最小功能验证数据导入、分析、建议和报告闭环；
- 防止产品成为功能很多但无法产生行动的演示程序。

### 2.8 企业B端购买与交付｜决定如何变现

需要理解：

- 企业采购流程；
- 决策者、使用者和审批者；
- PoC；
- ROI；
- 数据安全和部署方式；
- 试点成功标准；
- 单次诊断、订阅与企业集成的区别。

建议资料：

- *Lean B2B*。

典型相关角色：

- CTO；
- 云基础设施负责人；
- AI Infra或平台团队；
- FinOps；
- 财务和采购；
- 企业负责人。

客户购买的是可验证的成本、容量和风险改善，不是单独的算法指标提升。

### 2.9 GPU调度前沿｜最后按需跟进

建议关注：

- OSDI、NSDI、USENIX ATC、EuroSys、SC、ASPLOS；
- GPU Scheduler；
- Cluster Scheduler；
- Gang Scheduling；
- Ray、Volcano、Kueue、Slurm、SkyPilot、Run:ai；
- NVIDIA DGX Cloud。

学习目的：理解行业如何处理资源碎片、排队、公平性、弹性和多租户问题，为产品规则和长期路线提供输入。第一阶段不以复现底层调度论文为主。

## 3. 推荐学习顺序

```text
1. FinOps
   先理解客户为什么愿意为成本优化付费

2. Kubernetes与云计算
   理解GPU资源如何组织、调度和计费

3. GPU架构基础
   理解利用率、显存、共享和性能约束

4. 数据工程与数据质量
   可靠处理不同客户的数据

5. 容量预测
   从历史分析升级到未来规划

6. 运筹优化
   把预测转化为采购和资源配置行动

7. B2B产品与销售
   验证需求、PoC、ROI和购买流程

8. GPU调度前沿
   在实际需求出现后扩展产品能力
```

这些主线不是八门需要依次学完的课程。正确方法是围绕当前产品功能按需学习：先做一个功能，遇到必须判断的知识，再回到对应主线补足并把结论写入产品规则或可复用模板。

## 4. 与个人背景的匹配

工业工程、运筹优化和调度研究的优势，不是与 NVIDIA 工程师竞争 CUDA 内核，也不是立即与 Kubernetes 社区竞争底层调度器源码。

更适合建立的职业与产品位置是：

> 把运筹优化、数据分析、FinOps与GPU基础设施连接起来，形成企业能够使用和付费的资源决策产品。

产品价值需要用以下结果证明：

- 节省多少GPU成本；
- 避免多少不必要采购；
- 是否满足未来业务容量；
- 是否保护SLA；
- 建议能否执行；
- 风险与适用边界是否清楚。

“GPU调度性能提高2%”可能具有研究和工程价值；“在不破坏SLA的前提下减少可验证的GPU支出”通常更容易建立直接ROI。这个判断需要通过真实客户访谈和PoC继续验证，而不是仅凭技术实现假定成立。

## 5. 学习成果如何沉淀

每条知识主线只沉淀两类资产：

### 可复用模板

- 使用场景；
- 输入与输出；
- 固定工作流；
- 可替换位置；
- 公式或代码骨架；
- 验证规则；
- 常见错误。

### 展示型作品集

- 真实或合成但完整的业务问题；
- 可复现数据和代码；
- 方法选择；
- baseline；
- 结果验证；
- 成本、SLA和风险；
- 可运行产品或报告。

阅读记录、终端日志和零散知识点只是原料。只有进入产品规则、复用模板或完整作品集后，才成为资产。
