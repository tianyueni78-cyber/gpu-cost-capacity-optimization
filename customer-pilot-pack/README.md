# GPU 成本与利用率审计试点包

本试点用脱敏 CSV 回答三件事：GPU 钱花在哪里、资源如何使用、哪些调整值得进入人工审批。分析只读，不连接或修改生产环境。

## 适合的客户

- 每月已有持续 GPU 支出；
- 能导出资源、使用、账单和 SLA 数据；
- 有基础设施负责人参加结果确认；
- 当前缺少专职 FinOps 团队或统一分析口径。

只有合成数据、无法核对账单金额、无法提供资源与使用关联键，或者希望产品直接执行生产变更时，不进入付费试点。

## 请提供四张 CSV

复制 `templates/` 中的空白文件并填写。四张表必须覆盖同一个连续 7–31 天期间，时间统一使用 UTC，金额统一使用 USD。必填字段不得删除，暂时没有的可选字段保持空白。

| 文件 | 一行代表 | 关键要求 |
|---|---|---|
| `inventory.csv` | 一个 GPU 资源池 | `resource_pool_id` 唯一；数量、型号、区域和有效小时费率可核对 |
| `usage.csv` | 一个时间点的一条资源池观测 | 建议 5–60 分钟粒度；`resource_pool_id` 必须能关联资源清单 |
| `billing.csv` | 一条 GPU 账单费用 | 原始费用 − 折扣 = 净成本；保留真实费率和采购方式 |
| `sla.csv` | 一个团队和负载的服务约束 | 最低备用容量必填；未知约束不得填零 |

允许的 `procurement_model` 以客户原始账单为准，但同一种采购方式必须使用同一写法。`interruptible_allowed` 使用 `true` 或 `false`。未知指标留空，不用零代替缺失。

## 交付流程

1. 客户按[脱敏说明](脱敏说明.md)准备四张表。
2. 双方进行数据可用性检查；存在阻断项时先修复数据，不生成优化结论。
3. 按[30 分钟操作流程](30分钟操作流程.md)共同核对事实和约束。
4. 使用[结果审核清单](结果审核清单.md)确认哪些内容可进入内部审批。
5. 交付管理层报告、数据质量结果、建议明细和后续行动文件。

商业范围见[试点报价](试点报价.md)。
