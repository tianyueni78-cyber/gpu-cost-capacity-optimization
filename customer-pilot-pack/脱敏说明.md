# 客户数据脱敏说明

## 必须保留

以下信息决定成本、容量和 SLA 是否能正确计算，不应随机修改：

- GPU 型号、数量、区域和采购方式；
- 使用时间、分配数量、活跃数量、利用率和显存指标；
- 原始费用、折扣、净成本、计费时长和有效费率；
- SLA 数值、负载类型、共享或中断限制；
- 四张表之间稳定一致的关联关系。

## 应替换

使用稳定假名替换内部身份信息。相同对象在所有文件中必须使用相同假名。

| 原信息 | 替换示例 |
|---|---|
| 团队名称 | `TEAM-001` |
| 产品或项目名称 | `PRODUCT-001` |
| 资源池或实例标识 | `POOL-001` |
| 合同编号 | `CONTRACT-001` |
| 负责人姓名或邮箱 | 角色名，例如 `infra-owner` |

不要对关联键分别随机加密，否则四张表无法关联。不要对金额统一乘随机系数，否则折扣、费率和收益口径会失真。

## 不得提供

- 云账号密码、Access Key、Secret Key、Token 或 kubeconfig；
- 客户最终用户姓名、邮箱、手机号、地址或业务正文；
- 模型权重、提示词、训练样本、推理输入和输出；
- 与本次 GPU 分析无关的完整云账单；
- 未经授权的第三方数据。

## 交付前自检

- [ ] 四张表只包含约定的字段和分析期间；
- [ ] 已搜索并移除密钥、邮箱、手机号和自然人姓名；
- [ ] 同一团队、产品、资源池和合同的假名保持一致；
- [ ] 金额、数量、时间、型号、区域和 SLA 数值未被扰动；
- [ ] 文件可由客户指定负责人打开并抽查三条关联记录；

优先在客户电脑本地运行。确需传输文件时，双方先书面确认传输方式、访问人和删除日期。
