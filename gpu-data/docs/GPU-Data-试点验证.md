# GPU Data｜30 分钟客户试点

## 试点目标

验证客户是否愿意为“更快获得可信 GPU 成本与资源调查清单”付费，而不是验证图表是否漂亮。

试点成功必须同时满足：

- 客户认可账单金额和主要成本归属；
- 至少一条线索值得交给明确负责人继续调查；
- 客户理解相关成本不等于可节省金额；
- 客户愿意讨论付费诊断或接受明确报价。

## 会前准备

客户准备同一分析期间的四张脱敏 CSV：资源清单、使用记录、云账单和团队 SLA。演示人员提前确认文件可在客户电脑上读取，但不提前修改客户数据。

如果客户不能提供真实数据，使用合成案例演示产品能力，但不能把该场演示计为商业验证成功。

## 30 分钟流程

### 0—5 分钟：确认问题

只确认三个问题：本期 GPU 支出规模、最担心的资源问题、谁会根据结果采取调查行动。不开场介绍四产品套件。

### 5—12 分钟：数据接入

上传四张表，确认字段映射并运行审计。要求客户判断：阻断与警告是否符合其数据实际，修复责任人是否明确。

如果出现阻断项，试点仍可成功结束于“发现数据无法支持决策”，但不得绕过阻断继续展示结论。

### 12—20 分钟：当前状况

依次核对净成本、成本归属覆盖率、主要团队或资源池、GPU 库存、活跃数量和遥测覆盖。让客户现场复算一个金额或指标。

记录客户首次认可可信结果所用时间，目标不超过 15 分钟。

### 20—27 分钟：调查线索

选择优先级最高的一条线索，请客户回答：

1. 证据是否符合实际；
2. 哪个限制条件最重要；
3. 谁会负责核查；
4. 核查后可能触发什么决策。

不讨论释放数量或节省金额；如果客户主动询问，说明这属于 GPU Optimize 的独立分析。

### 27—30 分钟：导出与付费验证

导出 Markdown 报告及三个 CSV，然后提出明确问题：

> 如果以相同方式完成一次真实数据诊断并交付可核查报告，你是否愿意付费？如果愿意，可接受的试点价格或审批方式是什么？

记录原话，不用“感兴趣”代替付费证据。

## 记录表

| 指标 | 记录内容 |
|---|---|
| 首个可信结果时间 | 从上传开始到客户认可首个结果的分钟数 |
| 成本归属覆盖率 | 产品输出的百分比 |
| GPU 遥测覆盖率 | 产品输出的百分比 |
| 客户认可线索数 | 客户确认值得继续调查的线索数量 |
| 已指定负责人 | 是/否，以及负责人角色 |
| 可能触发的决策 | 数据修复、成本核对、配置评估或不行动 |
| 付费证据 | 接受报价、提出采购流程、拒绝及原因 |
| 产品边界误解 | 是否把相关成本误认为可节省金额 |

## 试点后的决策

- **继续 GPU Data：** 客户认可结果，但数据接入或解释仍需要改进；
- **开始 GPU Optimize：** 至少三名目标用户完成审阅、两名推动真实调查、一名接受付费或明确报价；
- **停止扩展：** 客户已有同等能力，或线索不能触发任何实际调查；
- **修复数据产品：** 多数试点因相同字段、口径或审计问题被阻断。

每次试点只更新已被真实客户证实的问题，不为假设需求增加功能。
