# GPU Forecast 正式规格

## 1. 产品目标

GPU Forecast 面向 AI 基础设施、FinOps、财务和业务负责人，将历史业务与 GPU 使用数据转化为可审批的容量、采购和预算计划。

产品必须回答：未来业务量是多少；按团队、GPU 型号和区域需要多少容量；何时出现缺口或过剩；最晚何时决策、采购多少以及预算多少。

## 2. 商业定位

本产品是 GPU 成本与容量决策平台的预测模块，不是孤立的时间序列演示：

```text
GPU Data 可信数据
→ GPU Forecast 需求与容量计划
→ GPU Optimize 约束下配置方案
→ GPU Improve 执行与收益验证
```

第一版提供只读决策和人工审批，不自动购买 GPU，不自动修改 Kubernetes 或生产集群。

## 3. 专业对标原则

| 能力 | 专业依据 | 本产品采用 | 第一版不采用 |
|---|---|---|---|
| 预测准入 | AWS Cost Explorer | 数据不足时拒绝正式预测；展示预测区间 | 复制 AWS 私有模型 |
| 容量视图 | Google Cloud Capacity Planner | GPU 型号、位置、使用量、预测、预留和配额同屏；分位数情景 | 自动申请云配额和预留 |
| 人机协同 | IBM Cloudability Intelligent Forecasting | 多模型比较、推荐模型、人工计划调整和发布 | 黑盒 AI 自动覆盖人工计划 |
| 财务计划 | Azure Cost Management | 预测成本用于预算、告警和价格情景 | 第一版直连全部云厂商 API |
| 工作方法 | FinOps Forecasting | 滚动预测、偏差管理、跨团队协作和持续复盘 | 建立企业级完整 FP&A 系统 |

专业对标决定规则和验收标准，不要求复制成熟平台的所有功能。

## 4. 第一版边界

### 支持

- 标准 CSV 和 GPU Data 标准输出；
- 邮箱登录、项目隔离和预测版本保存；
- 数据准备度与可预测性检查；
- 预测任务配置、滚动回测和多模型比较；
- 系统预测、业务事件和人工调整分层；
- P50、P90、P99 需求与容量情景；
- SLA、安全余量、库存、共享容量、预留和配额约束；
- 缺口日期、最晚决策日期、采购数量与预算；
- 历史预测和实际结果复盘；
- CSV、Markdown 计划及下游标准行动包导出。

### 不支持

- 自动采购、自动扩缩容或修改生产资源；
- 秒级在线预测；
- 深度学习模型和强化学习；
- 企业 SSO、复杂审批链和工单系统；
- 首版同时接入所有云厂商和监控系统；
- 在数据不足时生成伪精确建议。

## 5. 页面与工作流

```text
连接数据 → 预测准备度 → 配置任务 → 时间回测 → 人工计划
→ 容量情景 → 采购计划 → 发布版本 → 预测复盘
```

### 5.1 数据与范围

用户导入历史业务量、GPU 使用、资源清单、SLA、价格与交付周期，以及业务事件。系统检查时间连续性、缺失、异常峰值、口径变化、维度关联率和历史长度。

用户明确预测对象、团队、产品、GPU 型号、区域、时间粒度、预测期限和决策用途。系统输出：正式可预测、有限证据、不可预测。不可预测时阻断正式容量与采购建议。

### 5.2 预测工作台

系统采用滚动时间回测比较候选模型，显示实际值、历史预测、误差、偏差、区间覆盖率和推荐理由。系统预测与人工计划分开：

```text
发布预测 = 系统基线预测 + 已确认业务事件调整 + 人工调整
```

人工调整必须保存操作者、时间、原因、修改前后数值和基线版本，不得覆盖历史。

### 5.3 容量情景

系统按团队、型号、区域和周期将业务预测换算为 GPU 容量，并同时展示 P50、P90 和 P99 情景、库存、共享容量、已生效预留、配额、缺口及 SLA 风险。

型号不兼容不得合并，禁止跨区调配时不得跨区域抵扣；Spot 等不可保证容量不得作为关键 SLA 的确定容量。

### 5.4 计划与复盘

系统生成采购与扩容行动，包含缺口日期、建议数量、最晚决策日期、预计生效日期、采购方式、预算、证据等级和风险。负责人审批后，可导出到 GPU Optimize。

周期结束后，系统比较历史发布预测、实际业务量、实际 GPU 需求和实际成本，保留预测误差、人工调整效果、容量不足与闲置采购记录。

## 6. 输入数据契约

| 数据对象 | 最低字段 |
|---|---|
| 业务量 | 时间、团队、产品或负载、业务量、单位 |
| GPU 使用 | 时间、资源池、分配数量、活跃数量、GPU/显存利用率 |
| 资源清单 | 资源池、团队、型号、区域、数量、采购方式、生效期间 |
| SLA | 团队或产品、生效期间、可用性/延迟/排队阈值、最低备用容量 |
| 采购与价格 | 型号、区域、采购方式、有效费率、交付周期、配额或预留 |
| 业务事件 | 事件期间、影响范围、影响类型、预计幅度、确认状态 |

所有数量必须带单位；所有时间必须有明确时区或日/月定义；费用必须带币种和成本口径。

## 7. 预测准备度规则

以下任一情况阻断正式预测：

- 时间字段无法解析或数据顺序错误；
- 预测目标没有足够连续历史；
- 关键范围无法关联到团队、型号或区域；
- 指标单位或定义在历史中变化但没有分段；
- 训练数据包含预测期信息；
- 业务量与 GPU 容量无法建立可解释换算关系；
- 关键 SLA、库存或采购交付周期缺失。

异常峰值不得默认删除。业务事件造成的峰值保留并标记；采集错误修复后必须留下规则和对账证据。

## 8. 模型与回测标准

第一版至少比较：

1. 上一周期或季节性朴素基线；
2. 移动平均或指数平滑；
3. 趋势与季节模型。

必须采用滚动起点回测，禁止随机拆分时间序列。最低评价指标：

```text
MAE  = Σ|实际值 - 预测值| / n
WAPE = Σ|实际值 - 预测值| / Σ|实际值|
Bias = Σ(预测值 - 实际值) / Σ|实际值|
区间覆盖率 = 落入预测区间的实际观测数 / 总观测数
```

模型选择依据是决策损失、稳定性和可解释性，不只选择样本内拟合最好者。每个发布预测保存模型、参数、训练截止时间、数据指纹、回测窗口、误差和代码版本。

## 9. 容量换算标准

```text
基础 GPU 需求
= 预测业务量 ÷ 单位 GPU 有效产能

规划 GPU 容量
= 基础 GPU 需求 × SLA 安全系数 × 不确定性系数

容量缺口
= 规划 GPU 容量
- 当前可用容量
- 已确认可共享容量
- 预测期内已生效容量
```

单位 GPU 有效产能必须按负载类型、GPU 型号、区域或运行环境确定，并记录来源期间。训练、在线推理和批处理不能使用同一个未经验证的换算系数。

公司总量必须由团队、型号、区域明细汇总并对账；不得先预测公司总量再任意分配到明细。

## 10. 情景与采购规则

| 情景 | 用途 | 默认依据 |
|---|---|---|
| P50 | 常规经营与弹性容量 | 中位预测 |
| P90 | 稳健容量和预算 | 较高需求分位数 |
| P99 | 关键 SLA 压力测试 | 极端但可解释的需求范围 |

```text
最晚决策日期 = 预计缺口日期 - 采购或交付周期 - 审批缓冲期
预算 = 各型号、区域、采购方式的计划数量 × 适用期间有效费率
```

长期承诺只覆盖可预测的稳定基线；增长不确定部分和峰值容量单独列示。预测不能直接替代 GPU Optimize 的约束优化。

## 11. 核心数据对象

- `projects`：用户和项目范围；
- `forecast_jobs`：预测对象、范围、粒度和期限；
- `data_snapshots`：输入版本、截止时间和数据指纹；
- `backtest_runs`：模型、窗口、误差和覆盖率；
- `forecast_versions`：不可变的系统预测与发布预测；
- `forecast_adjustments`：业务事件和人工计划调整；
- `capacity_scenarios`：分位数、容量、约束和缺口；
- `purchase_plans`：采购数量、时间、预算、风险和审批状态；
- `forecast_actuals`：实际结果和偏差复盘。

用户数据必须通过项目所有权实施行级隔离。原始客户明细第一版只在当前计算会话处理；数据库保存经过确认的摘要、版本、配置和结果。

## 12. 证据等级

| 等级 | 条件 | 是否允许发布采购建议 |
|---|---|---|
| HIGH | 数据完整、滚动回测稳定、区间覆盖合理、容量换算有验证 | 是 |
| MEDIUM | 回测通过但部分事件或产能参数依赖人工确认 | 是，必须展示风险 |
| LOW | 历史较短、结构变化明显或回测不稳定 | 仅发布观察性情景 |
| UNVERIFIABLE | 数据、时间、单位、关联或换算存在阻断 | 否 |

## 13. 错误与安全边界

- 数据不足必须拒绝，不自动补出未来值；
- 预测区间不得描述为确定承诺；
- 人工调整与系统预测不得互相覆盖；
- 历史预测版本禁止更新或删除；
- 费用、容量和业务量必须保留独立字段；
- 采购建议必须经过人工审批；
- 页面和报告不得声称系统已执行采购或生产变更；
- 密钥不得进入代码仓库，客户端不得使用数据库 service-role key。

## 14. 商品化路线

### MVP

Streamlit、Supabase、CPU 预测模型、CSV/GPU Data 输入和文件导出。无需自有 GPU，适合演示、顾问试点和首批客户验证。

### 商业试点

增加定时任务、邮件告警、项目协作、云账单或监控系统的一个真实连接器，以及预测发布审批。

### 企业版本

增加多租户计费、企业 SSO、角色权限、审计导出、数据驻留、服务监控和多个生产连接器。只有客户明确接受后才考虑自动执行。

## 15. 硬性验收标准

- 四页流程可独立运行；
- 数据不足和时间泄漏均有自动阻断测试；
- 至少三类模型和一个朴素基线完成滚动回测；
- 显示预测区间，不能只输出单点；
- 系统预测、事件调整和人工计划可分别追溯；
- 历史预测版本不可覆盖；
- P50/P90/P99 能换算成型号、区域和团队容量；
- 明细容量与公司总量完成对账；
- 采购计划考虑交付周期、审批缓冲和价格期间；
- LOW 与 UNVERIFIABLE 不得生成正式采购承诺；
- 历史预测可以与实际结果复盘；
- 能导出预测、容量情景、采购计划和管理摘要；
- 输出可被 GPU Optimize 接收；
- 不包含自动生产变更能力；
- 全部自动测试、Python 编译、Streamlit 页面测试和健康检查通过。
