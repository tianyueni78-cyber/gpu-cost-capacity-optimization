# GPU Forecast Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 构建可独立运行的 GPU Forecast MVP，将可信历史数据转化为可回测、可调整、可版本化的业务预测、GPU 容量情景和采购计划。

**Architecture:** 使用纯 Python 领域模块承载数据准入、时间回测、预测、容量换算、采购计划和报告，Streamlit 只负责四页交互。Supabase 仅保存用户项目、配置、摘要、不可变预测版本和计划；原始客户明细默认停留在当前会话。模块通过稳定 dataclass 和 DataFrame 契约衔接 GPU Data、GPU Optimize。

**Tech Stack:** Python 3.11+、pandas 2.2+、NumPy 1.26+、Streamlit 1.40+、Supabase Python 2.15+、unittest、PostgreSQL RLS。

**Spec:** `gpu-forecast/正式规格.md`

## Global Constraints

- 产品仅提供预测、容量和采购决策建议，不自动采购或修改生产资源。
- 第一版只实现季节性朴素、指数平滑、趋势季节三类可解释模型，不引入深度学习依赖。
- 时间序列只能按时间滚动回测，禁止随机拆分和使用预测期信息。
- 系统预测、业务事件调整和人工调整必须分别保存，发布版本不可覆盖。
- LOW 只允许观察性情景；UNVERIFIABLE 不得生成正式采购建议。
- 预测必须输出区间，并至少支持 P50、P90、P99 容量情景。
- 容量必须按团队、GPU 型号、区域和周期计算，明细汇总必须与总量对账。
- 原始客户业务和使用明细不长期写入 Supabase；密钥不提交仓库，前端不得使用 service-role key。
- 每个任务执行失败测试、最小实现、全量回归和独立提交。
